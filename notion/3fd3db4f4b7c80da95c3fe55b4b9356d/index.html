回溯

原理

如何更好地理解回溯，我会建议大家多画递归树。

想象你在走迷宫。你来到了一个三岔路口（决策点），你选择走左边。走着走着发现是一条死胡同（不满足条件），这时候你该怎么办？你必须退回到刚才的三岔路口，撤销刚才“走左边”的决定，然后尝试走中间那条路。这个过程就是回溯。

在code里，我们把所有可能的情况看作一棵决策树。回溯算法其实就是在这棵树上进行深度优先遍历（DFS），写dfs的时候需要想清楚以下几个问题再开始：

  1. 路径： 你已经做出的选择。
  2. 选择列表： 你当前可以做的选择。
  3. 结束条件： 到达决策树底层，无法再做选择。

最核心的在于“撤销选择”。如果你不撤销，你的程序就会永远记录着错误的路，无法去探索新的分支。

记忆化搜索

很多时候，当你在考场上推不出复杂的动态规划状态转移方程，或者状态极其稀疏、难以进行迭代时，记忆化搜索往往能救你一命！因为他的写法非常类似我们熟悉的dfs，也就是暴力搜索的过程，是非常可套路化的。

原理

要理解记忆化搜索，必须理清回溯、记忆化搜索和动态规划的关系

回溯/ 暴力DFS

  • 本质就是一种暴力全量搜索，把所有可能性都枚举出来。
  • 缺点：做了大量重复劳动。比如计算斐波那契数列，算 f(5) 需要算 f(4) 和 f(3)，算 f(4) 又要算 f(3) 和 f(2)……你会发现 f(3) 被重复计算了多次。
  • 复杂度：通常是指数级，如O(2n)O(2^n)O(2n)。

记忆化搜索

  • 每次算出一个状态的结果，我就把它记下来。下次再遇到这个状态，我查一下缓存直接返回，绝不重复计算。
  • 本质：自顶向下的动态规划。它保留了DFS的递归逻辑，但剪去了重复的搜索树枝。
  • 复杂度：通常降维到多项式级，如O(n2)O(n^2)O(n2)或O(n⋅W)O(n⋅W)O(n⋅W)。

动态规划

  • 不再递归地去“问”问题，而是根据依赖关系，从最小的问题开始，一行一行地把表格填满。
  • 本质：自底向上的递推。

记忆化搜索是通向DP的最佳桥梁。只要你能写出暴力的DFS，加上两行代码（查表、记录），它就变成了记忆化搜索；如果你再仔细观察记录表的填写顺序，反过来写循环，它就变成了迭代式DP。

代码

什么时候该用记忆化搜索，而不是迭代式 DP？

虽然大多数教程推崇迭代式 DP（省内存、常数小），但在实战中，以下情况我首选记忆化搜索：

  • 状态稀疏：如果你的 DP 数组是 dp[10000][10000]，通过迭代你需要填满一亿个格子。但实际上可能只有几千个状态是合法的、会被访问到的。记忆化搜索只会计算到达的状态，天然自带“剪枝”效果。
  • 状态转移复杂：有些题目（如树形DP、图上的博弈论），你很难确定遍历的顺序（是从左到右？还是斜着？）。记忆化搜索不需要管顺序，只要逻辑对，递归会自动帮你找到依赖链。
  • 路径输出：递归结构在回溯路径、打印方案时往往更符合人类直觉。

又或者这样说：如果笔试的时候，你可以很快地使用记忆化搜索来解题，大部份情况下都是可以ac的（主要你的复杂度是合法的），此时就不用去硬写迭代dp了。

动态规划

DP 的本质就是在有向无环图（DAG）上求最短/最长路，或者做拓扑排序上的递推。

一个问题要想用 DP 解决，必须具备两个核心特征：

  1. 重叠子问题：暴搜在执行过程中，会反复遇到一模一样的状态。DP 通过将这些状态的结果存下来（记忆化），避免了重复计算。【这也就是记忆化搜索的思想】
  2. 最优子结构（无后效性）：全局的最优解必然是由局部的最优解推导出来的。当前的“状态”一旦确定，未来的决策就不依赖于过去你是怎么走到这一步的。

DP 解题三个步骤

面对一道 DP 题目，建议进行以下三步推演：

  1. 状态定义 ：dp[…] 究竟代表什么意义？（这是最核心的一步，维度开少了不够用，维度开多了不仅爆内存，转移也复杂）。
  2. 状态转移方程 ：已知状态怎么推导未知状态？（寻找“最后一步”的决策，把大问题拆成比它小一号的问题）。
  3. 边界条件与初始化：最基础的、无需计算即知的状态是什么？（通常是 i=0、空串或者容量为 0 的情况。求最大值通常初始化为负无穷，求最小值初始化为正无穷）。

线性dp

在之前的拆解中，我们提到 DP 的本质是 DAG（有向无环图）上的递推。

在“线性 DP”中，这个 DAG 的拓扑序非常直白——它就是数组或序列的自然下标顺序（从前往后，或从后往前）。

这意味着，状态的推导是在一个线性的维度上单向推进的。求解第 i 个阶段的状态，通常只依赖于第 i-1个阶段，或者依赖于前 i-1 个阶段中的某几个特定状态。

经典模型 1：最长上升子序列 (LIS)

LIS (Longest Increasing Subsequence) 问题是理解“状态定义如何限制最后一步”的非常好的一个例子。

题意：给定一个无序的整数数组，找到其中最长且严格递增的子序列的长度。

推演逻辑

很多同学的第一反应是定义 dp[i] 为“前 i 个元素中的最长上升子序列长度”。

这个定义是错的或者说极其难转移的，因为如果你不知道这个子序列的最后一个元素是什么，你就无法判断第 i+1 个元素能不能接在它后面！

  • 状态定义：dp[i] 表示以第 i 个元素为结尾的最长上升子序列的长度。（强制把 nums[i] 包含进去，这样我们就明确了子序列的尾部大小）。
  • 状态转移方程：要想计算 dp[i]，我们需要往前看所有的 j（0≤j<i0≤j<i0≤j<i）。只要 nums[j] < nums[i]，说明 nums[i] 可以完美地接在以 nums[j] 结尾的上升子序列后面。
  • dp[i]=max(dp[i],dp[j]+1)dp[i]=max(dp[i],dp[j]+1)dp[i]=max(dp[i],dp[j]+1)，其中 j<ij<ij<i 且 nums[j]<nums[i]nums[j]<nums[i]nums[j]<nums[i]
  • 边界条件：每个元素自身都可以构成一个长度为 1 的子序列，所以 dp 数组初始化全为 1。全局的最终答案不是 dp[n-1]，而是整个 dp 数组中的最大值。

代码模板

经典模型 2：最大子段和

如果说 LIS 需要回头看前面所有的状态，那么最大子段和（也常被称为 Kadane 算法）则是“只看前一步”的例子。

题意：给定一个整数数组 nums ，找到一个具有最大和的连续子数组（子数组最少包含一个元素），返回其最大和。

推演逻辑

  • 状态定义：连续子数组意味着不能跳跃。我们定义 dp[i] 为以第 i 个元素为结尾的连续子数组的最大和。
  • 状态转移方程：站在第 i 个元素的位置，你只有两个选择：
    • 自立门户：前面的兄弟是个负资产（dp[i-1] < 0），带上他只会拖累我，我不如从自己这重新开始，此时和为 nums[i]。
    • 抱团取暖：前面的兄弟是正资产（dp[i-1] > 0），带上他能让总和更大，此时和为 dp[i-1] + nums[i]。
    • dp[i]=max(nums[i],dp[i−1]+nums[i])dp[i]=max(nums[i],dp[i−1]+nums[i])dp[i]=max(nums[i],dp[i−1]+nums[i])
  • 空间优化：发现了吗？dp[i] 只依赖于 dp[i-1]。在笔试中，我们完全可以把 O(N) 的空间复杂度压缩到 O(1)，只用一个变量记录前一个状态即可。

代码模板

经典模型 3：最长公共子序列 (LCS )

题意：给定两个字符串 A 和 B（长度分别为 n 和 m），求它们的最长公共子序列的长度。子序列不要求在原串中连续。

推演逻辑

  • 状态定义：dp[i][j] 表示字符串 A 的前 i 个字符和字符串 B 的前 j 个字符的 LCS 长度。
  • 状态转移方程：比较 A 的第 i 个字符和 B 的第 j 个字符：
    • 如果 A[i−1]==B[j−1]A[i-1] == B[j-1]A[i−1]==B[j−1]：说明这个字符可以作为公共子序列的一部分，直接由两个字符串都退一步的状态推导而来：dp[i][j]=dp[i−1][j−1]+1dp[i][j]=dp[i−1][j−1]+1dp[i][j]=dp[i−1][j−1]+1
    • 如果A[i−1]!=B[j−1]A[i−1]!=B[j−1]A[i−1]!=B[j−1]：说明这两个字符不可能同时出现在 LCS 的末尾。我们要么抛弃 A 的当前字符，要么抛弃 B 的当前字符，取两者中的较大值：dp[i][j]=max(dp[i−1][j],dp[i][j−1])dp[i][j]=max(dp[i−1][j],dp[i][j−1])dp[i][j]=max(dp[i−1][j],dp[i][j−1])

代码模板

线性 DP 的核心技巧

拿到序列问题，第一时间会在脑海中建立这样的映射：

  1. “连续子数组” / “子串”→状态定义通常强制以 i 结尾，转移时只看 i-1。
  2. “不连续子序列”→状态定义同样常以 i 结尾，但转移时通常需要枚举j<ij<ij<i，或者使用二维状态 dp[i][j]（比如 LCS）。

背包问题

01背包

问题模型

给定 N 个物品和一个容量为 V 的背包。第 i 个物品的体积是 w[i]，价值是 v[i]。每个物品最多只能用一次，求将哪些物品装入背包可使价值总和最大。

核心逻辑

对于第 i 个物品，我们只有两种决策：拿 或者 不拿。

我们定义状态 dp[i][j] 表示：在前 i 个物品中选择，且背包容量不超过 j 时，能获得的最大价值。

  • 不拿第 i 个物品：问题退化为在前 i-1 个物品中用 j 容量能获得的最大价值，即 dp[i-1][j]。
  • 拿第 i 个物品：既然决定拿，那必须先给它腾出 w[i] 的空间。于是问题变成了：在前 i-1 个物品中用 j-w[i] 容量获得的最大价值，加上当前物品的价值 v[i]，即dp[i−1][j−w[i]]+v[i]dp[i−1][j−w[i]]+v[i]dp[i−1][j−w[i]]+v[i]。

状态转移方程：dp[i][j]=max(dp[i−1][j],dp[i−1][j−w[i]]+v[i])dp[i][j]=max(dp[i−1][j],dp[i−1][j−w[i]]+v[i])dp[i][j]=max(dp[i−1][j],dp[i−1][j−w[i]]+v[i])

空间压缩

观察上面的方程，你会发现第 i 行的状态只依赖于第 i-1 行。这意味着我们根本不需要保留所有历史，只需要一个一维数组 dp[j] 滚动更新即可。

压缩后的方程变成了：dp[j]=max(dp[j],dp[j−w[i]]+v[i])dp[j]=max(dp[j],dp[j−w[i]]+v[i])dp[j]=max(dp[j],dp[j−w[i]]+v[i])

为什么 j 的遍历必须逆序遍历？

在一维数组下，当我们计算 dp[j] 时，我们期望用到的是上一层（即 i-1 状态）的 dp[j-w[i]]。

  • 如果正序遍历（从 0 到 V），当我们算到 dp[j] 时，dp[j-w[i]] 可能已经在当前这层被更新过了（相当于被拿了多次），这就违背了01背包“每个物品只能拿一次”的限制。
  • 如果逆序遍历（从 V 到 w[i]），当算到 dp[j] 时，它左边的 dp[j-w[i]] 还绝对没有被更新过，完美保留了上一层的干净状态。

完全背包

问题模型

给定 N 种物品和一个容量为 V 的背包。第 i 种物品的体积是 w[i]，价值是 v[i]。每种物品都有无限件可用，求最大价值。

核心逻辑

既然每种物品有无限件，我们的决策就不再是“拿或不拿”，而是“拿 0 件、拿 1 件、拿 2 件……拿 k 件”。

理论上的状态转移方程非常复杂，需要多一层循环去枚举件数，但是这样复杂度过大了，我们要用等效替代的思维来优化。

考虑我们要拿第 i 个物品，因为物品无限，我们在拿了之后，依然可以继续拿第 i 个物品。

所以，拿第 i 个物品的状态依赖不再是上一层的 dp[i-1][j-w[i]]，而是当前层已经更新过的状态 dp[i][j-w[i]]。

优化后的二维状态转移方程：dp[i][j]=max(dp[i−1][j],dp[i][j−w[i]]+v[i])dp[i][j]=max(dp[i−1][j],dp[i][j−w[i]]+v[i])dp[i][j]=max(dp[i−1][j],dp[i][j−w[i]]+v[i])

注意这里的第二个参数是 dp[i] 而不是 dp[i-1]。

空间压缩

同样的，我们将其压缩为一维数组：dp[j]=max(dp[j],dp[j−w[i]]+v[i])dp[j]=max(dp[j],dp[j−w[i]]+v[i])dp[j]=max(dp[j],dp[j−w[i]]+v[i])

公式长得和01背包一模一样！区别到底在哪？就在遍历顺序。

01背包为了防止重复拿，必须逆序。而完全背包正需要重复拿！我们要的就是“在已经拿过当前物品的状态上，继续拿”。因此，完全背包必须正序遍历。

树形dp

树形 DP 的本质是在树状结构上进行的递推。由于树本身具有天然的递归属性（子树也是树），所以我们通常利用 DFS 来实现从子节点向父节点的状态转移。

在树形 DP 中，我们通常定义 dp[u] 为：以 u 为根的子树在满足某种约束下的最优解。

流程：从根节点出发进行 DFS，先递归处理所有子节点，在回溯时（即子节点信息已确定）根据子节点的状态更新父节点。

状态转移方程的一般形式：dp[u]=f(dp[v1],dp[v2],…,dp[vk])dp[u]=f(dp[v1],dp[v2],…,dp[vk])dp[u]=f(dp[v1],dp[v2],…,dp[vk])，其中 v 是 u 的子节点。

代码模板

题目往往给出的是无向边。我们首先需要建立邻接表，然后从任意节点（通常是 1 号节点）开始 DFS。为了防止在无向图中走回头路，DFS 时需要记录一个 fa（父亲节点）。

区间dp

适用场景

  1. 在一个区间上进行操作
  2. 将多个元素不断合并成一个整体
  3. 或将一个大整体拆分成单个元素
  4. 每次只能操作相邻的两个部分
  5. 操作产生代价，求代价的最值

核心思想

将一个大区间的问题拆解成若干个小区间的问题，先求解小区间，再利用小区间的结果推导出大区间的最优解。

本质上是一种按照区间长度递增的动态规划。

区间 DP 的三个核心要素

1. 状态定义：dp[i][j]

通常定义：dp[i][j]=区间 [i,j] 的最优解dp[i][j]=\text{区间 }[i,j]\text{ 的最优解}dp[i][j]=区间 [i,j] 的最优解

具体可以表示：

  • 区间 [i,j] 的最大得分。
  • 区间 [i,j] 的最小合并代价。
  • 区间 [i,j] 是否满足某种条件。
  • 区间 [i,j] 的方案数量。

与普通线性 DP 不同，区间 DP 使用两个下标表示一个子问题的左右边界。

2. 状态转移：枚举分割点 k

假设我们要求区间 [i,j] 的最优解，可以枚举一个分割点 k，将大区间拆成两个小区间：

典型状态转移方程：
dp[i][j]=min⁡i≤k<j(dp[i][k]+dp[k+1][j]+cost(i,j,k))dp[i][j]=\min_{i\le k<j}\left(dp[i][k]+dp[k+1][j]+cost(i,j,k)\right)dp[i][j]=mini≤k<j​(dp[i][k]+dp[k+1][j]+cost(i,j,k))

其中：

  • dp[i][k]：左子区间的最优解。
  • dp[k+1][j]：右子区间的最优解。
  • cost(i,j,k)：将两个子问题组合起来的额外代价。

注意：不是所有区间 DP 都必须枚举分割点。有些题目只需要考虑区间左右端点的选择，例如最长回文子序列。

3. 遍历顺序：先小区间，后大区间

这是区间 DP 最重要的特点。

状压dp

当问题的规模非常小（通常N≤20）且涉及到集合的选取、排列或连通性时，会使用一个整数的二进制位来表示一个集合的状态。

“状态压缩”，听起来高大上，其实说白了就是用一个整数的二进制表示来记录一个集合的状态。

在常规的DP中，我们可能需要用一个布尔数组 visited[20] 来记录哪些节点已经被访问过。但是在状态转移时，把数组作为状态存进DP表中不仅空间开销大，而且非常难以作为数组的索引（用记忆话搜索的思想来题解，就是这个东西无法被缓存）。

怎么办？计算机底层是用二进制的，我们完全可以用一个整数的二进制位来替代这个布尔数组。

例如，集合中有5个元素，状态整数为11=(01011)211=(01011)_211=(01011)2​：

  • 第0位是1：第0个元素被选中
  • 第1位是1：第1个元素被选中
  • 第2位是0：第2个元素未被选中
  • 第3位是1：第3个元素被选中
  • 第4位是0：第4个元素未被选中

这样，原本需要一维数组记录的状态，现在被“压缩”成了一个在[0,25−1][0,2^5−1][0,25−1]范围内的整数！

在写状压DP前，你必须对以下位运算形成肌肉记忆：

  1. 判断第 i 位是否为 1：(state >> i) & 1
  2. 将第 i 位设为 1：state | (1 << i)
  3. 将第 i 位设为 0：state & ~(1 << i)
  4. 翻转第 i 位：state ^ (1 << i)
  5. 获取最低位的 1（lowbit）：state & -state

核心原理

状压DP本质上还是DP，核心仍是状态表示和状态转移。状压DP主要分为两类经典模型：集合最短路模型（如TSP问题）和棋盘/网格模型。

经典类型：旅行商问题 (TSP - Traveling Salesperson Problem)

题目描述：给定一个 N 个城市的完全图（N≤20），以及两两城市之间的距离矩阵 dist。求从0号城市出发，经过所有城市恰好一次，最后回到0号城市的最短路径长度。

状态定义：

我们用一个二进制数 S 表示当前已经访问过的城市集合。

定义 dp[S][i] 表示：当前已访问过的城市集合为 S，且当前恰好停留在城市 i 时的最短路径总长度。
