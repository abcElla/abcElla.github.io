记忆化搜索

本篇目录
  1. 原理
  2. 代码
  3. 什么时候该用记忆化搜索，而不是迭代式 DP？

很多时候，当你在考场上推不出复杂的动态规划状态转移方程，或者状态极其稀疏、难以进行迭代时，记忆化搜索往往能救你一命！因为他的写法非常类似我们熟悉的dfs，也就是暴力搜索的过程，是非常可套路化的。

原理

要理解记忆化搜索，必须理清回溯、记忆化搜索和动态规划的关系

回溯/ 暴力DFS

  • 本质就是一种暴力全量搜索，把所有可能性都枚举出来。
  • 缺点：做了大量重复劳动。比如计算斐波那契数列，算 f(5) 需要算 f(4) 和 f(3)，算 f(4) 又要算 f(3) 和 f(2)……你会发现 f(3) 被重复计算了多次。
  • 复杂度：通常是指数级，如O(2n)O(2^n)O(2n)。

记忆化搜索

  • 每次算出一个状态的结果，我就把它记下来。下次再遇到这个状态，我查一下缓存直接返回，绝不重复计算。
  • 本质：自顶向下的动态规划。它保留了DFS的递归逻辑，但剪去了重复的搜索树枝。
  • 复杂度：通常降维到多项式级，如O(n2)O(n^2)O(n2)或O(n⋅W)O(n⋅W)O(n⋅W)。

动态规划

  • 不再递归地去“问”问题，而是根据依赖关系，从最小的问题开始，一行一行地把表格填满。
  • 本质：自底向上的递推。

记忆化搜索是通向DP的最佳桥梁。只要你能写出暴力的DFS，加上两行代码（查表、记录），它就变成了记忆化搜索；如果你再仔细观察记录表的填写顺序，反过来写循环，它就变成了迭代式DP。

代码

什么时候该用记忆化搜索，而不是迭代式 DP？

虽然大多数教程推崇迭代式 DP（省内存、常数小），但在实战中，以下情况我首选记忆化搜索：

  • 状态稀疏：如果你的 DP 数组是 dp[10000][10000]，通过迭代你需要填满一亿个格子。但实际上可能只有几千个状态是合法的、会被访问到的。记忆化搜索只会计算到达的状态，天然自带“剪枝”效果。
  • 状态转移复杂：有些题目（如树形DP、图上的博弈论），你很难确定遍历的顺序（是从左到右？还是斜着？）。记忆化搜索不需要管顺序，只要逻辑对，递归会自动帮你找到依赖链。
  • 路径输出：递归结构在回溯路径、打印方案时往往更符合人类直觉。

又或者这样说：如果笔试的时候，你可以很快地使用记忆化搜索来解题，大部份情况下都是可以ac的（主要你的复杂度是合法的），此时就不用去硬写迭代dp了。
